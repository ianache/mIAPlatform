## 1. ¿Qué es una **cita externa** y por qué es importante en el contexto de una concesionaria?

| Concepto | Descripción breve | Impacto en la concesionaria |
|----------|-------------------|-----------------------------|
| **Cita externa** | Registro de una interacción entre la concesionaria y un cliente que ocurre **fuera del taller propio** (ej.: visita a un taller asociado, revisión en la fábrica, inspección externa, servicio de terceros). | • Permite rastrear todo el historial del vehículo, sin importar dónde se haya atendido.<br>• Facilita la trazabilidad para garantías, seguros y cumplimiento normativo.<br>• Mejora la experiencia del cliente al ofrecer una visión única y completa de sus servicios. |
| **Datos típicos** | • Identificador de la cita (UUID)<br>• Fecha/hora<br>• Tipo de servicio (mantenimiento, inspección, reparación, etc.)<br>• Proveedor externo (nombre, identificación fiscal, ubicación)<br>• Detalle de los trabajos realizados y piezas usadas<br>• Evidencias (fotos, PDF, videos)<br>• Estado de la factura y pago | • Estos datos deben ser **consistentes**, **auditables** y **protegidos** bajo los requisitos de ISO 27001/27016. |

## 2. **Qdrant** como base de conocimientos para la gestión de citas externas

Qdrant es una **base de datos vectorial** (vector similarity search) que permite almacenar y consultar datos semánticos a gran escala. En el caso de las citas externas, Qdrant resulta útil para:

| Necesidad | Cómo Qdrant la cubre | Ventajas |
|-----------|----------------------|----------|
| **Búsqueda semántica de citas** (ej.: “mostrar todas las inspecciones de frenos realizadas por talleres fuera de la zona norte en los últimos 6 meses”). | Indexa los **embeddings** generados a partir del texto descriptivo de cada cita (tipo de servicio, notas del mecánico, observaciones del cliente). | - Respuestas rápidas (milisegundos).<br>- No depende de palabras exactas; entiende sinónimos y errores tipográficos. |
| **Recomendación de talleres externos** (sugerir al cliente el taller más adecuado según historial del vehículo). | Almacena embeddings de los perfiles de talleres (especialidades, certificaciones, rating) y realiza *nearest‑neighbor* contra el embedding del vehículo o de la última cita. | - Personalización en tiempo real.<br>- Escalable a miles de talleres. |
| **Detección de anomalías** (citas que se alejan del patrón típico de un modelo de vehículo). | Calcula la distancia vectorial entre la nueva cita y el “centro” del clúster de citas históricas del mismo modelo. Distancias fuera de umbral → alerta. | - Mejora la detección temprana de fraudes o errores de registro. |
| **Integración con IA** (chatbot que responde preguntas como “¿Cuándo fue la última revisión de frenos que hice fuera del taller oficial?”). | El chatbot genera un embedding de la pregunta y lo compara con los embeddings de citas; devuelve la cita más parecida. | - Interfaz natural para usuarios y empleados. |

### 2.1. Modelo de datos en Qdrant (ejemplo)

```json
{
  "id": "cita-7f3a9b2c-4d5e-11ee-8c3f-0242ac130003",
  "vector": [0.12, -0.04, 0.87, …],          // embedding (384‑dim, por ejemplo, de un modelo BERT)
  "payload": {
    "fecha": "2025-11-23T10:30:00Z",
    "tipo_servicio": "Inspección de frenos",
    "proveedor_externo": {
      "nombre": "Taller AutoFrenos S.L.",
      "cif": "B12345678",
      "latitud": 40.416775,
      "longitud": -3.703790
    },
    "vehiculo_id": "VIN-1HGCM82633A004352",
    "kilometraje": 87500,
    "piezas_utilizadas": ["Pastilla de freno Del. 45", "Disco delantero 410mm"],
    "nota_tecnica": "Desgaste avanzado en disco delantero, se recomienda cambio en 5000 km.",
    "archivos": [
      {"url":"https://s3.amazonaws.com/.../foto1.jpg","tipo":"foto"},
      {"url":"https://s3.amazonaws.com/.../informe.pdf","tipo":"pdf"}
    ],
    "estado_factura": "pendiente",
    "tags": ["frenos","exterior","urgente"]
  }
}
```

* **Vector** → generado con un modelo de embeddings (por ejemplo, `sentence‑transformers/all-MiniLM-L6-v2` o un modelo propio entrenado con el dominio de talleres).  
* **Payload** → datos estructurados que pueden usarse como filtros (`filter: { "must": [{"key": "proveedor_externo.nombre", "match": {"value": "AutoFrenos"}}]}`).

### 2.2. Operaciones típicas

| Operación | API de Qdrant | Comentario de seguridad |
|-----------|---------------|--------------------------|
| **Insertar/actualizar cita** | `POST /collections/{name}/points` | Validar esquema JSON contra **JSON‑Schema** y firmar la petición con JWT/HMAC (ISO 27001 A.9.2). |
| **Buscar por texto** | `POST /collections/{name}/search` (vector + `filter`) | Aplicar **control de acceso basado en roles (RBAC)**: solo usuarios con permiso *cita:read* pueden consultar. |
| **Eliminar cita (GDPR)** | `DELETE /collections/{name}/points?ids=...` | Registrar en **log de auditoría** (ISO 27001 A.12.4) y aplicar retención mínima requerida. |
| **Crear snapshot (respaldo)** | `POST /collections/{name}/snapshots` | Almacenar snapshots en **cifrado en reposo** (AES‑256) y replicar a varias regiones para alta disponibilidad. |

## 3. Arquitectura de **microservicios** para gestionar citas externas con Qdrant

A continuación, se muestra un **esquema de referencia** que combina:

* **Microservicios** desacoplados, cada uno con su propio dominio de datos.
* **Qdrant** como motor de búsqueda semántica.
* **Patrones de seguridad** alineados a ISO 27001 y ISO 27016 (gestión de riesgos de la información y de la continuidad del negocio).

### 3.1. Diagrama de alto nivel (texto)

```
+-------------------+      +-------------------+      +-------------------+
|   API Gateway     | <--->| Auth & Identity   | <--->|  IAM (Keycloak)   |
+-------------------+      +-------------------+      +-------------------+
          |                           |                     |
          |   REST/GraphQL, gRPC      |                     |
          v                           v                     v
+-------------------+   +-------------------+   +-------------------+
|  Cita Service     |   |  Taller Service   |   |  Vehiculo Service |
|  (CRUD + Rules)   |   |  (Catálogo)       |   |  (Histórico)      |
+-------------------+   +-------------------+   +-------------------+
          |                           |                     |
          |  Event Bus (Kafka)        |  Event Bus (Kafka)  |
          v                           v                     v
+---------------------------------------------------------------+
|                     **Qdrant Vector Store**                  |
|  - Colección `citas_externas`                                 |
|  - Colección `talleres`                                       |
|  - Colección `vehiculos` (embeddings)                        |
+---------------------------------------------------------------+

+-------------------+      +-------------------+      +-------------------+
|  Notification     | <--->|  Reporting/BI     | <--->|  Auditing Service |
|  Service (SMS/Email) |   | (PowerBI, Superset) |   | (Immutable log) |
+-------------------+      +-------------------+      +-------------------+
```

#### Descripción de los componentes

| Componente | Responsabilidades | Tecnologías recomendadas |
|------------|-------------------|--------------------------|
| **API Gateway** | Enrutamiento, rate‑limiting, transformación de protocolos, exposición de endpoints públicos. | Kong, Traefik, Envoy (con mTLS). |
| **Auth & Identity** | Autenticación (OAuth2.0 / OpenID Connect), emisión de JWT con claims de roles. | Keycloak, FusionAuth. |
| **Cita Service** | - CRUD de citas externas.<br>- Validaciones de negocio (p.ej. que el taller tenga certificación).<br>- Publicación de eventos `CitaCreada`, `CitaActualizada`. | Spring Boot (Java) / .NET Core / NestJS (Node) – *containerizado* (Docker). |
| **Taller Service** | Catálogo de talleres externos, gestión de certificaciones y disponibilidad. | Go / Rust (alto rendimiento). |
| **Vehiculo Service** | Historial del vehículo, generación de embeddings (texto de notas, informes). | Python (FastAPI) + *sentence‑transformers* para embeddings. |
| **Event Bus** | Comunicación asíncrona entre servicios, desacoplamiento y resiliencia. | Apache Kafka (con **encryption at rest** y **ACLs**). |
| **Qdrant** | Almacenamiento vectorial y búsqueda semántica. | Desplegado en **K8s** con **StatefulSets**, replicación 3‑zone, TLS mutuo. |
| **Notification Service** | Envío de confirmaciones, recordatorios y alertas de anomalías. | AWS SNS / Azure Notification Hubs (cifrado). |
| **Reporting/BI** | Dashboards de desempeño de talleres, SLA, métricas de uso. | Superset, Grafana, PowerBI (con OIDC). |
| **Auditing Service** | Registro inmutable de operaciones críticas (creación, borrado, cambios de estado). | ElasticSearch + OpenSearch + **WORM** (write‑once‑read‑many) storage. |

### 3.2. Flujos típicos

#### 3.2.1. Creación de una cita externa
1. **Cliente (app móvil/web)** envía solicitud `POST /citas` al **API Gateway** con JWT.
2. Gateway verifica **RBAC** (`cita:create`) contra el **IAM**.
3. **Cita Service** valida datos (formato, existencia del vehículo, certificación del taller).
4. Se genera un **embedding** de la descripción de la cita (service de *Embedding* en `Vehiculo Service`).
5. `Cita Service` persiste la entidad en su base relacional (PostgreSQL) y envía el punto a **Qdrant** (`upsert`).
6. Publica evento `CitaCreada` en Kafka.
7. **Notification Service** consume el evento y envía email/SMS al cliente.
8. **Auditing Service** graba la operación con hash SHA‑256 y firma digital (ISO 27001 A.12.4.1).

#### 3.2.2. Búsqueda semántica de citas
1. UI solicita “citas de frenos realizadas por talleres fuera de Madrid en los últimos 3 meses”.
2. El **frontend** envía la frase al **API Gateway**, que la redirige al **Cita Service**.
3. **Cita Service**:
   - Genera embedding de la frase.
   - Llama a **Qdrant** con `search` (vector + filtros por `fecha` y `proveedor_externo.localidad`).
4. Qdrant devuelve los IDs de las citas más relevantes.
5. `Cita Service` recupera los registros completos de PostgreSQL y los devuelve al cliente.
